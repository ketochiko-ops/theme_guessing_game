# お題当てオンライン（仮）

ゲームマスター(GM)1名 vs プレイヤー(P1, P2)2名で遊ぶ、リアルタイムのお題当て対戦ゲームです。
出題者と回答者に分かれて、Socket.IOの同期機能を用いたチャット形式で進行します。

## 使用技術
- Frontend: React, Bootstrap 5, Vite
- Backend: Node.js (Express), Socket.io, SQLite3

## 🎮 ゲーム概要
GMが決めた「お題」を、2人のプレイヤーが交互に質問しながら先に当てることを競います。

### 役割
- **GM (Game Master)**: お題を設定し、プレイヤーの質問に回答します。ゲームの進行（開始・一時停止・リセット）を管理します。
- **プレイヤー (P1, P2)**: 交互にターンが回ってきます。自分のターンでは「質問」「お題回答」「パス」のいずれかを行えます。
- **観戦者 (Observer)**: お題や全プレイヤーのやり取り、システムログをすべて閲覧できますが、ゲームには介入できません。

### 基本ルール
1. GMがお題を入力し、ゲームを開始します。
2. P1から順にターンが回ります。
3. プレイヤーは自分のターンに：
   - **質問**: GMに質問を投げます。送信中、そのプレイヤーのタイマーは停止します。
   - **お題回答**: お題をズバリ当てます。正解すれば勝利、不正解ならライフが1減り、相手のターンになります。
   - **パス**: 何もせず相手にターンを渡します。
4. ライフが0になるか、相手に正解されると敗北です。

### スコア計算
勝利したプレイヤーのスコアは以下の式で算出されます：
`スコア = (残りライフ × 1000) - (累計消費時間(秒) × 1) - (質問回数 × 10)`
※スコアは0点を下限とします。

## ✨ 主な機能
- **リアルタイム同期**: Socket.ioによる低遅延な状態管理。
- **スマートチャット**: 
  - システムログ、全体チャット、ゲーム進行（質問・回答）を1つのタイムラインに統合。
  - フィルタ機能（すべて / P1関連 / P2関連 / システム）により、必要な情報のみを抽出可能。
  - 入力文字数を最大100文字に制限し、荒らし対策。
  - 投稿時間を非表示にし、モバイルでの視認性を向上。
- **モバイル最適化**: vw単位を用いた可変文字サイズ、画面高さを固定したアプリライクなUI。
- **お知らせ機能**: `public/info.csv` を編集することで、トップ画面に動的なお知らせを表示（URLの自動リンク化対応）。
- **部屋番号自動発行**: GMがトップ画面で「GM」を選択すると、5桁の数字が自動で割り振られます。

## 💻 ローカル開発手順

1. **パッケージのインストール**
   ```bash
   npm install
   ```
2. **開発サーバーの起動**
   ```bash
   npm run dev
   ```
   フロントエンド(Vite)とバックエンド(nodemon)が同時起動します。
   ブラウザで `http://localhost:5173/` (Vite側のポート) にアクセスして操作してください。
   (APIおよびWebSocketの通信は `http://localhost:8080` へプロキシされます)

## 🐛 デバッグ方法

- **ブラウザ側**: Chrome等のDevToolsのコンソールタブを開き、コンポーネントのログやSocketの接続状態(`Connecting...`, `Socket connected`)を確認できます。
- **サーバー側**: `npm run dev` を実行しているターミナルに、ユーザーの入室(`User connected: ...`)や、クリーンアップ処理のログ(`Cleaned up old room...`)が出力されます。

## 🚀 Koyeb デプロイガイド

KoyebのNanoインスタンスでデプロイすることを想定した設定です。

1. **GitHubリポジトリの作成とプッシュ**
   このプロジェクトをGitHubリポジトリにプッシュします。

2. **KoyebでのApp作成**
   - デプロイのソースとして「GitHub」を選択。
   - 対象のリポジトリを選択。

3. **ビルドおよびラン・コマンド設定**
   Koyebのデプロイ設定画面で、オーバーライド設定(Override)を使用します。
   - **Build Command**: `npm run build`
   - **Run Command**: `npm start`
   - *(補足: `package.json`には `npm start` 時に `node server.js` を実行するように記述されています)*

4. **ポート設定 (PORT)**
   - Expose(公開ポート)の設定で、ポート番号を `8080` に設定します。
   - Expressサーバー側で `process.env.PORT` を優先して受け取るようになっているため、Koyebが指定したポートで自動的に立ち上がります。

5. **データ永続化における注意事項**
   - 本ゲームでは SQLite3 をファイル(`database.sqlite`)で管理しています。
   - Koyebの仕様上、デプロイや再起動によってローカルファイルは初期化されます。進行中のセッションはリセットされますが、1回ごとの短期ゲームであることを前提とした仕様です。
